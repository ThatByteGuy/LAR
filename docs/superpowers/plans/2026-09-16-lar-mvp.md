# LAR MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship CLI-first MVP that analyzes untrusted AUR build instructions before execution.

**Architecture:** Layered CLI -> orchestrator -> pure security engine (input -> AnalysisReport); AUR/makepkg/pacman adapters only at edges. No daemon, no sandbox yet.

**Tech Stack:** Rust, clap derive, reqwest rustls, tokio, regex, url, thiserror/anyhow, tracing, tempfile.

**Spec:** Architectural Decisions (2026-09-16) + LAR-overview.md — verdicts UNKNOWN/ANALYZED/SUSPICIOUS/BLOCKED/VERIFIED, no SAFE, local BLOCK wins, fail-closed.

## Global Constraints

- Never `source`/`eval`/`bash PKGBUILD` to analyze; no `sh -c` with interpolation.
- No `unwrap`/`expect` outside tests; `Result` + thiserror lib / anyhow app.
- No `unsafe` in MVP.
- Offline-first; online never downgrades local BLOCK.
- Minimal deps; no second package DB; no /var/lib/pacman writes.
- TDD red-green-refactor; corpus must guard false positives.
